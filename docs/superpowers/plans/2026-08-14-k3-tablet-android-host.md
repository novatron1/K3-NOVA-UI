# K3 Tablet Android Host Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make K3-NOVA-UI capable of using a real trusted Nova/K3 HTTPS host and produce a directly installable Android debug APK while preserving the existing safe fake-host GitHub Pages demo.

**Architecture:** Keep the UI/controller boundary unchanged. Add a client-safe runtime configuration parser, an `HttpPresentationHost` implementation of the existing `PresentationHostAdapter`, and a root component that selects demo or remote mode. Package the Vite `dist` bundle with pinned Capacitor 8.4.2 tooling in a dedicated Android CI job without adding provider credentials or long-lived secrets to the client.

**Tech Stack:** React 19, TypeScript 5.9, Vite 8, Vitest 4, existing presentation event validator, Fetch API, Capacitor 8.4.2 build tooling, Android/Gradle generated by Capacitor, GitHub Actions.

## Global Constraints

- Preserve the existing `PresentationHostAdapter` interface and `NovaMindApp` UI behavior.
- Public GitHub Pages must continue to default to fake-host demo mode.
- No K3/Kimi/cloud provider API key or long-lived administrative token may be embedded in Vite env, browser assets, Android resources, or committed files.
- Remote mode accepts HTTPS by default; insecure HTTP is only allowed when explicitly enabled for development/LAN testing.
- Node.js remains `>=22.13.0`.
- Capacitor tooling is pinned to `8.4.2`.
- `npm ci` and the existing lockfile remain deterministic; Capacitor packages are installed `--no-save --package-lock=false` only in Android bootstrap/build steps.

### Task 2: Real HTTPS presentation host adapter

**Files:**
- Create: `src/host/http-presentation-host.ts`
- Create: `tests/host/http-presentation-host.test.ts`

**Interfaces:**
- Consumes: `PresentationHostAdapter`, `PresentationHostHandlers`, `PresentationSession`, `validateHostEvent`, remote `HostConfig` base URL.
- Produces: `HttpPresentationHost`.

Expected protocol:
- `POST /v1/presentation/sessions`
- `POST /v1/presentation/sessions/{id}/text`
- `POST /v1/presentation/sessions/{id}/voice-transcript`
- `POST /v1/presentation/sessions/{id}/permissions/{approvalRequestId}`
- `POST /v1/presentation/sessions/{id}/cancel`
- `DELETE /v1/presentation/sessions/{id}`

Example focused test shape:
```ts
const requests: Array<{ url: string; method: string; body?: string }> = [];
const fetchImpl: typeof fetch = async (input, init) => {
  requests.push({
    url: String(input),
    method: init?.method ?? "GET",
    body: typeof init?.body === "string" ? init.body : undefined,
  });
  return new Response(JSON.stringify({ sessionId: "s1", events: [] }), {
    status: 200,
    headers: { "content-type": "application/json" },
  });
};
```

- [ ] Write tests for session creation and event delivery.
- [ ] Write tests for exact text/voice/permission/cancel/close routes and JSON bodies.
- [ ] Write tests for malformed JSON, missing session IDs, invalid events, non-2xx responses, and lifecycle abort behavior.
- [ ] Implement response parsing that never renders raw backend error bodies and validates every presentation event before forwarding it.
- [ ] Ensure fatal failures call only `invalid_event` or `host_unavailable` and only once.
- [ ] Keep teardown requests independent from an already-aborted controller lifecycle signal so best-effort cancel/close can still reach the backend.
- [ ] Run focused host tests.
